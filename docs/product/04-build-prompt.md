# Sync is a release-critical contract

1. Each device mutation commits the visible local write and its serialized outbox operation together. A process death immediately after the write preserves both or neither. Separate confirmed server base from pending overlay. Cache, queue and current binding are partitioned by account. A late result must check authenticated account, dataset epoch and connection/session generation before touching state. Surface saving, offline pending, action required and synced states inclusively.
2. Authenticate account and device, validate payload shape, bind request to a dataset epoch and installation generation, then handle version preconditions. Under one short per-account revision transaction, atomically commit the authorized change, ordered change group, receipt and any required transactional outbox. All writers including jobs and integrations participate. An ordinary SQL sequence alone cannot order transactions by commit. The same operation ID and canonical payload returns its committed result. Reuse with a different payload is rejected. Preserve receipt lifetime or an equivalent expiry/fencing policy that keeps old requests from executing again. Keep network calls outside domain transactions.
3. Use stable IDs per meal item, set, recipe/plan version and source record. Merge independent records when rules permit. Two edits to the same record require expected version or an explicit merge strategy. A stale edit cannot revive an account-scoped tombstone. Preserve competing user intent and offer keep server, reapply applicable edits or explicitly create a new record where permitted. Show resolved/rejected operations accurately.
4. Pull ordered revisions with a pinned upper bound for paginated passes, bounded payloads and a cursor advanced atomically with application. Keep a captured high-water for snapshots, lease the change window as needed, atomically replace the confirmed base and replay deltas/pending intent. Handle cursor expiry, retry/backoff with jitter, restoration to older server data and revoked devices. Rotate a restored dataset's generation outside its restored state. Reapply current erasure/revocation protections before serving a restored snapshot. Unknown/lost acknowledgement outcomes must reconcile before a side effect can repeat.
5. Sync on foreground/resume, local commits and regained connectivity with bounded background work. Treat optional realtime notices as a hint to pull. Never make timely background execution an invariant. Never silently overwrite a local draft on pull. Require separate tests for session completion, history corrections, timezone/backdated entries, simultaneous changes, old client replay, account switching and restore. Replay Watch messages only with correct account and Watch binding generation. Keep IDs stable across transport and provider retries.
